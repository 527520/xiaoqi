## B-2 · ★ 需要你决定：FTS5 在本机**实现不了**记忆检索所需的中文子串检索

**状态**：等你拍板（这是 §8 第 3 类：发现规格自相矛盾）
**影响**：M3 记忆系统的检索层怎么实现。**不阻塞其它任何事。**

### 规格怎么说的

施工令 §5 M3 原文：

> **FTS5 全文检索**（**不引入任何向量库**——记忆规模是千条级，
> FTS + 时间/情绪/标签过滤完全够用，且比向量检索更可解释）

`docs/verification.md` V1 还给了背书：

> **FTS5 全文检索可用**：`MATCH '加班'` 命中"用户昨天也在加班"
> 中文分词：FTS5 默认 `unicode61` 对中文按字切分，子串检索可用

### 实测是什么

原样复刻 V1 那个用例（`node scripts/recheck-v1-fts5.mjs`）：

```
MATCH '加班'                     → 0 条    ← V1 声称这里有 1 条
MATCH '加' / '昨天' / '也在加班'   → 均 0 条
MATCH '用户昨天也在加班'           → 1 条    ← 用**整句**查才命中
```

原因：**FTS5 默认分词器把整句中文当成一个 token**。
用 `fts5vocab` 直接看切出来的 token，只有 1 个：`用户昨天也在加班`。
所以"能查到"只发生在"拿原句查原句"，**任何真子串都查不到**。
V1 当时的结论很可能就是这么得来的——它验的是"原句能查到原句"。

换 trigram 分词器也不行（`node scripts/probe-fts5-strategy.mjs`）：

```
A. 默认 FTS5（unicode61）      命中 0/7
B. trigram FTS5                命中 0/7
C. trigram + 短查询 LIKE 兜底   命中 5/7   ← 靠的其实是 LIKE
D. 纯 LIKE（对照）             命中 5/7
```

`5/7` 里"漏掉的 2 个"是 `开会`、`摸鱼` —— 它们**本来就不在测试数据里**
（数据里写的是"讨厌开长会"）。所以真实情况是 **LIKE 5/5，两种 FTS5 都是 0/7**。

### 为什么这是"自相矛盾"而不是"我该自己决定"

规格给的**理由**是"千条级规模下 FTS 够用、且更可解释"，
而规格给的**方案**（FTS5）在本机**恰恰实现不了它要的检索**。
理由成立、方案落空——这不是技术选型偏好问题。

另外它踩到了 §1.2⑪「删掉的记忆必须真的消失」（不同方案对删除留痕的处理不同）。
「不引入向量库」这条我**不会**违反，下面三个选项都不涉及向量库。

### 三个选项

| 选项            | 做法                                                                | 代价                                                                                           |
| --------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **A（我推荐）** | 检索用 `LIKE '%词%'`，配合时间/情绪/标签的普通索引；**不建 FTS 表** | 全表扫描。千条级 ≈ 微秒级，两千条也毫无压力。但**字面上偏离了"用 FTS5"**                       |
| B               | 保留 FTS5 表，但只当"整句/长片段"索引用；检索主路径仍走 LIKE        | 多一张表、多一套触发器要保持同步，实际收益接近零                                               |
| C               | 自写 bigram 分词：写入时把中文切成 2 字滑窗存进 FTS 表，查询同样切  | 检索能用上 FTS5，但**要自己维护分词与查询改写**，代码量与出错面明显变大；收益只是"用上了 FTS5" |

我建议 **A**：它满足规格的**理由**（不引向量库、千条级够用、可解释），
只是不用 FTS5 这个**手段**——因为该手段在这台机器上达不到目的。
若你更看重"照字面执行规格"，选 C 我可以实现，但会在
`docs/DECISIONS.md` 里写明它为什么更复杂而收益更小。

### 无论选哪个，我都会做这两件事

1. **更正 `docs/verification.md`**：V1 那条"中文子串检索可用"是错的，
   追加一段实测更正（**只追加，不覆盖既有结论**，符合施工令的要求）。
2. **把探测脚本留在仓库里**（`scripts/recheck-v1-fts5.mjs` 等），
   让这个结论可复现、可被质疑。
