# 回顾：用真实用户视角自我评审

施工令 §8 要求：每完成一个里程碑问自己「如果我是用户，这东西会在什么时候惹我烦？」
并据此调整默认值。**这份文件的每一条都要落到代码或文档里，否则就只是感想。**

---

## M1（垂直切片）

### 「什么时候会惹我烦」清单

| 场景                                       | 会不会惹烦               | 现状与处置                                                                                                              |
| ------------------------------------------ | ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 我在全屏看视频/打游戏，它还在上面动        | **会，非常烦**           | 已处理：QUNS `{1,2,3,4}` → 自动静默（缩成小点）。**但端到端未人眼验证**（见 `docs/verify-m1.md` 证据 6）                |
| 它挡住我右下角的按钮                       | **会**                   | 已处理：透明留白**逐轮廓穿透**，不是整窗挡住。8/9 项端到端验证里有专门的判别性用例                                      |
| 我想把它挪开却拖不动                       | **会**                   | ⚠️ **M1 没做拖动**。它默认贴在工作区右下角，只能通过托盘"回到默认位置"或改缩放间接挪。**这是 M1 最明显的缺口**，列入 M2 |
| 它太大/太小，我调不了                      | **会**                   | 已处理：托盘的"大小"档位（75/100/125/150/200%）。这是用户明确提出的需求                                                 |
| 同事从旁边走过看到我的屏幕上有个奇怪的东西 | **会**                   | 已处理：`Ctrl+Shift+H` 一键隐身 + 捕获排除（录屏/共享时也看不到）。**不宣传成防截屏**——手机拍屏依然拍得到               |
| 我想让它消失，但找不到怎么关               | **会**                   | 已处理：托盘菜单 + 全局快捷键，两条路都在                                                                               |
| 它一直动，我余光里很闹                     | 轻微                     | 已处理：待机降到 8fps、呼吸幅度 3.5%、每 2.4–7s 才眨一次眼。**静默态（4fps）几乎不动**                                  |
| 笔记本上它把电吃光                         | **会，而且是隐形差评源** | 已处理：待机 ≤10fps（施工令 §4.3⑩ 的硬要求），隐藏时停更。但**本机是台式机，耗电无法实测**                              |
| 它盯着我看让我不自在                       | 不会                     | 反而是我刻意做的：眼睛跟着光标转是这只宠物的签名元素。**注意**：只在光标靠近时跟，远离就回正——不构成"一直盯着"          |
| 鼠标划过它时误点/误拖                      | 不会                     | 需要真的按下去才响应（`pointerdown`）。划过不做任何事                                                                   |

### 据此做的默认值决定

1. **主动度**：M1 没有任何主动说话的能力（还没有人设与表达层），所以这条在 M1 上
   天然满足。M5 接入表达层时**默认必须低**，已在 `docs/ARCHITECTURE.md` 的
   配置 schema 里把 `proactiveness` 默认写死成 `0.15`。
2. **大小默认 100%**，不是更大。桌宠占屏幕面积越大越容易招人烦；
   用户想大可以自己调。
3. **开机自启默认关**（schema 里 `autoStart: false`），且引导里不提。
4. **感知全部默认最低**（schema 里三项为 `true` 但窗口标题恒 `false` 且不暴露开关）。

### M1 暴露出的、我判断错了的地方

1. **我低估了"好看"的难度。** 施工令 §4.5 说"不接受一个丑陋的占位方块"，
   我原以为按几何画出来就够。实际做到第五版尾巴才成立，
   而配色第一版直接落进了"这类产品最常见的默认长相"（暖奶油 + 深棕 + 粉）。
   **教训**：程序化角色的"好看"不是几何正确就自动得到的，
   它需要独立的设计决策（光源统一、暖色只放在活的地方、次级动作），
   以及**反复截图比对**。这部分没有可自动化的判据。
2. **我的诊断工具本身会骗我。** M1 排查"宠物没有眼睛"花了很久，
   最后发现一半原因是 React 19 StrictMode 下 `window.__petDebug`
   可能指向**已销毁的实例**——那个死实例的场景图"看起来完全正常"。
   我据此撤回了一条错误结论（见 `docs/verify-m1.md`）。
   **教训**：诊断工具的可信度必须先被验证，否则它会系统性地把人带偏。
3. **守卫必须反向验证。** 图标脚本的"防漂移自检"里正则有 bug
   （`[^}]*` 会跨形状边界），核对永远通过却没在核对它以为在核对的东西。
   是我**故意改错一个字段看它会不会报**才发现的。
   **教训**：一个永远为真的守卫比没有守卫更危险。

### 留到 M2 的事

- **拖动**：用户最自然的"挪开它"的动作，M1 没做。优先级高。
- 自定义位置持久化（现在重启回到右下角）。
- 全屏静默的人眼确认（需要用户配合跑 `XIAOQI_KEEP_OPEN_MS`）。
- 多屏与混合 DPI（本机只有一块屏）。
