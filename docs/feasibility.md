# 桌面宠物 · 可行性分析

> 分析对象：设计文档《一个住在你桌面上的 AI 生命体》
> 分析机器：Windows，2560x1440 单屏，Node 24.15 / Python 3.14（**无 Rust 工具链、无 pnpm、无 git 仓库**）
> 实测方式：`probe/perception-probe.ps1`（零依赖探针，已在本机跑通）

## 零、先给结论

**能做，而且你文档里的绝大部分构想都在能力范围内。但它的天花板不由"能不能读到"决定，而由"读到之后能干什么"和"用户凭什么信你"决定。**

三句话：

1. **你不是读不到，你是读了也没用。** 很多应用（受保护进程、独家全屏游戏、UAC 安全桌面、DRM 视频）**根本读不到**——这些不是待攻克的技术难题，是操作系统的安全设计，绕过它们等于写病毒。但更关键的是：即便你读到了内容，你也**做不了任何事**，因为你无法安全地操作别人的窗口。
2. **你需要的信号比你想的少得多。** 只需三个信号——**前台进程名 + 系统空闲时长 + 键鼠活动强度**——就能推出你文档里 90% 的"工作模式"。不碰 OCR、不碰内容、纯本地。**从 L0 到 L1 覆盖 80% 场景，L1 往上边际收益递减而法律与信任成本陡增。**
3. **最大的风险不是技术，是打扰、隐私、道德绑架**（这点你自己已经写对了）。技术侧的三个隐形杀手是：透明窗口在全屏应用里消失/闪烁、录屏时没自动隐身导致社死、常驻动画耗电被笔记本用户直接卸载。

**一个反直觉的发现（本机实测）**：你以为 L1（前台应用名+窗口标题）是"低隐私风险、默认开"，实测 `msedge` 的窗口标题是完整的网页标题：

```
msedge :: 升级 PowerShell 并安装 rg — DeepSeek Harness 和另外 5 个页面 - 个人 - Microsoft Edge
```

只要用户在浏览器里打开公司内网、银行、ChatGPT 对话，这个"低风险"的 L1 **就等于在读正文摘要**。你的分级表在这一格上标错了，后面第八节会给出修正方案。

## 一、硬边界：这些读不到，而且不该去读

先划死线。下面每一条都是我在正文中不再重复讨论的**永久性禁区**：

| 禁区 | 为什么读不到 | 强行绕过的后果 |
|---|---|---|
| 受保护进程（PPL）、部分杀软/银行客户端 | 内核级保护，`OpenProcess` 直接拒绝 | 触发杀软告警，被当恶意软件 |
| 游戏内（反作弊内核驱动） | 反作弊主动封杀外部读取与注入 | **封号** |
| 独占全屏（exclusive fullscreen） | 不经过 DWM 合成，覆盖层根本画不出来 | 无法绕过，只能退出全屏 |
| UAC 提权弹窗、登录/锁屏界面 | 独立安全桌面，进程被隔离 | 属于恶意软件行为 |
| DRM 视频（Netflix/Prime 等） | 硬件级保护路径，截出来是黑屏 | 违反 DMCA 类法律 |
| macOS：其他应用窗口文字 | 需要「辅助功能」权限，且 App Store 沙盒应用**拿不到** | 无法上架 Mac App Store |
| macOS：屏幕内容 | 需要「屏幕录制」权限，用户不授予就完全不可用 | 首次启动即弹窗，劝退率高 |
| macOS：全局键鼠钩子 | 需要辅助功能权限；沙盒下不可用 | 同上 |
| Windows：跨进程键鼠钩子 | UIPI 完整性级别隔离，读不到管理员窗口 | 提权 + 杀软告警 |

**核心区分（这决定了整个产品的技术路线）**：

> **能读 ≠ 能操作。** 你无法可靠地"点别人的按钮、读别人的输入框"。任何需要"帮用户操作另一个应用"的设计（自动调暗屏幕、自动填邮件温柔版、自动发消息）在商业软件里基本不可行——要么做不到，要么做得极其脆弱。

## 二、能力阶梯：它最多能做到哪种程度

按难度和风险分层，**这就是这个产品的真实天花板**：

| 级别 | 能力 | 技术手段 | 难度 | 风险 | 备注 |
|---|---|---|---|---|---|
| **A** | 渲染自己、动画、气泡、声音、桌面物件 | 透明置顶窗 + 点击穿透 + 精灵/Live2D | 低 | 无 | 完全可控，v0.1 必须先打穿 |
| **B** | 系统集成：托盘、全局快捷键、系统通知、任务栏进度、开机自启 | 各平台壳 API | 低 | 无 | 稳定可靠，性价比最高 |
| **C** | **知道自己"在什么场景"**：前台进程名、空闲时长、全屏/锁屏、电量、时间 | 轻量轮询，100% 本地 | **低** | **中** | 桌面宠物的"智能感"就住在这里 |
| **D** | 内容级理解：OCR、读代码、读邮件正文 | 截屏 OCR / 厂商扩展 / IDE 插件 | 高 | **极高** | 收益小、风险大，且大部分应用读不到 |
| **E** | 操作其他应用：自动点按、代填内容、改系统设置 | UIA 写入 / 注入 | 极高 | 高 | **商业软件中基本不可行** |
| **F** | 读取受保护应用 | —— | 不可能 | —— | 见第一节，直接放弃 |

**关键结论：C 级就是你的主战场，D/E/F 不该投入。**

补充 C 级的两个易踩坑（已写进探针，实测有效）：

- **全屏检测必须用物理像素比对**。150% DPI 缩放下，最大化窗口的逻辑矩形永远不等于显示器矩形，用错方法会静默失效。探针里用 `DWMWA_EXTENDED_FRAME_BOUNDS` + `EnumDisplayMonitors` 物理边界解决。
- **必须过滤 cloaked 窗口**。UWP 被挂起的窗口、其他虚拟桌面上的窗口，不判断 `DWMWA_CLOAKED` 就会被误认成"前台"。

## 四、少感知，多推断（最重要的一节）

### 三个信号，覆盖你文档里 90% 的场景推断

| 场景 | 仅用「前台进程 + 空闲时长 + 活动强度」能否推出 |
|---|---|
| 编码模式 | ✅ 前台是 IDE/终端 |
| 会议模式 | ✅ 前台是会议软件（**再用麦克风占用交叉验证，准确率更高**） |
| 邮件模式 | ✅ 前台是邮件客户端 |
| 休息/娱乐模式 | ✅ 长时间无输入 + 视频网站进程 |
| 加班模式 | ✅ 时间 + 前台是 IDE |
| 疲劳模式 | ✅ 连续活动时长超阈值 |
| 下班/周末 | ✅ 时间 + 活动强度骤降 |
| 专注模式 | ✅ 前台应用长时间不变 + 持续输入 |

**没有一项需要读屏幕内容。** 你文档里 L3/L4/L5（OCR、代码内容、邮件正文、摄像头、麦克风）投入产出比是全表最低的，而且每一项都在消耗用户信任。

### 为什么"少感知"是战略而不是妥协

- 边际收益递减：L0→L1 拿 80% 场景，L1 往上每次只多 5–10%。
- 信任是启动成本：桌宠是要**常驻**的软件。第一次授权弹窗越吓人，安装转化越低。一个装完就弹"我要读取你的屏幕"的桌宠，用户会直接卸载。
- **记忆才是护城河，感知不是。** 感知层极容易被抄；但"用户 × 时间"这张账没有任何现成替代品，用户离开时也带不走。这才是撑起日活和留存的东西。**资源和时间应该压在记忆系统上，而不是感知层。**

### 修正你文档里的分级授权表

你的 L1 标成"低风险、默认开"是**错的**——实测证明窗口标题会泄露网页内容（见开头零节）。

建议改成**按进程白名单授权**，而不是按"数据类型"分级：

```
感知:
  应用识别:     开      # 只拿进程名/可执行文件路径 —— 这个确实低风险
  窗口标题:     按应用   # 默认仅对 IDE / 终端 / 会议 / 邮件客户端开启
                        # 浏览器、密码管理器、银行、隐私窗口默认关闭
  活动事件:     询问
  屏幕内容:     关
  音频/麦克风:  关
```

理由：**"前台是 VS Code" 和 "前台是某银行网页" 的隐私风险差了两个数量级，但它们在你的表里都属于 L1。** 按数据类型分级是设计错误，按应用分级才对。

## 五、你那三个"最容易翻车点"，技术上还有四个没写

你列的三个（打扰、隐私、道德绑架）是对的，都是产品伦理问题。技术侧还有四个隐形杀手：

1. **透明窗口 × 全屏应用。** 独家全屏游戏里桌宠会消失；共享 GPU 表面上会出现闪烁或黑边。这决定"隐身态"能不能做到优雅——**做不好就是每次开会都闪烁的尴尬。**
2. **屏幕共享自动隐身 —— 你的"隐身态"是全清单最难的技术项。** 准确判断"我正在被录屏/共享"在各平台都没有干净的 API。务实方案：
   - Windows：`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 可让自己**不被截取**（这是真 API，能兜底防社死）
   - 但"检测他人正在录屏"仍不完美，可组合：检测录制进程存在 + 检测 RDP 会话 + 检测独占全屏
   - **诚实建议：把"自动隐身"做成"尽力而为 + 提供手动一键隐身快捷键"，并且手动那条路径必须是 100% 可靠的。**
3. **耗电。** 透明窗 + 常驻动画会持续占 GPU。笔记本用户会看到风扇转起来然后卸载。做法：点击/气泡时唤醒渲染，待机降到 5–10fps 或直接暂停。**不要常驻 60fps。**
4. **企业 WiFi 会让社交层直接失灵。** mDNS/组播在企业网络里普遍被禁（客户端隔离、多播阻断是标准安全配置）。所以：

> **社交层的成败不在发现机制，而在降级路径。** 必须同时支持：手动配对码、局域网 IP 直连、以及（可选）云端中继。只做 mDNS 的产品，测试机上一个都发现不了，演示时就是灾难。

另外提醒一句合规：你文档第八节"桌宠八卦"在办公环境里涉及**员工监控**的观感。即便你只交换抽象化数据，**"我的桌宠把我在加班这件事告诉了同事的桌宠"** 在员工眼里可能就是监控。这一层默认必须是**关**，而且首次开启要有一段人话说明。这一点你的文档写对了，这里只是强调：它不是"隐私敏感"，是"可能引发 HR 层面问题"。

## 八、重新定义 MVP：先做验证，不要先写业务

我建议把 v0.1 之前插一个**一周技术验证期**，五天五问。这五件事任何一件没过关，后面所有业务代码都白写：

| Day | 验证什么 | 过关标准 |
|---|---|---|
| 1 | 透明窗 + 点击穿透 + 多屏 + 150% DPI 缩放 | 宠物能站在桌面任何位置，点击穿透到下层，缩放不糊不错位 |
| 2 | 全屏应用下的表现 + 屏幕共享时 `WDA_EXCLUDEFROMCAPTURE` 是否生效 | 看视频/玩游戏时不闪不残留；录屏时确实拍不到宠物 |
| 3 | 最小感知探针 | 本机跑 `probe/perception-probe.ps1`，确认能稳定识别 IDE/浏览器/会议软件，并统计有多少应用给出空标题 |
| 4 | 本地 LLM 延迟基准 | 测出"用户点它 → 第一句气泡出现"的真实秒数。**超过 2 秒就必须重做交互设计**（改成先出模板句、LLM 后补） |
| 5 | mDNS 在真实办公网络 + 手机热点下的发现率 | 若办公网发现率为 0，社交层必须先做手动配对 |

然后 v0.1 砍到真正的"最小生命体"：

- 形象渲染 + 状态机 + 情绪
- 状态引擎（C 级感知）+ 工作模式识别
- **3 个技能**：夸夸便签、呼吸圈、专注花园
- 本地记忆（SQLite）
- 人设配置
- **一键隐身（手动快捷键，必须 100% 可靠）**

**明确排除在 v0.1 之外**：社交层、OCR、音频、邮件读取、技能市场。你的路线图把社交放在 v0.4 是对的，但"技能市场化"不该等到 v0.5——**插件架构要在 v0.1 就定好，否则 v0.5 是一次重写而不是一次扩展。**

---

## 九、总评

| 维度 | 评价 |
|---|---|
| 技术可行性 | **高**。A/B/C 级全部可行，且不需要任何越界手段 |
| 最能出彩的地方 | 状态引擎的"懂你"感 + 记忆系统的长期陪伴感。**不是感知能力** |
| 最大技术难点 | 屏幕共享自动隐身；透明窗口的跨平台稳定性 |
| 最大产品风险 | 打扰（自己做对了）；**感知过度导致的安装转化崩塌**（你的 L1 分级标错了） |
| 已被证伪的构想 | 锁屏诗（系统锁屏不可改）、会议内容理解（需录音）、邮件正文读取（拿不到草稿）、自动操作其他应用 |
| 最该改的一件事 | **放弃"感知越多越智能"的假设，改成"少感知、多推断"，把省下的资源全押在记忆系统上** |
| 最该警惕的一件事 | 17 个技能同时存在会互相稀释。核心 3–5 个，其余走插件 |

**一句话可行性结论**：这个产品技术上做得出来，天花板在 C 级感知 + 深度记忆 + 精致表达，**不需要、也不应该碰屏幕内容**。它最终的上限不取决于你读到了多少，而取决于它记得多少、以及它多么懂得在该消失的时候消失。
